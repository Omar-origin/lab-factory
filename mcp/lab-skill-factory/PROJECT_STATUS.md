当前阶段：v2.1 报告自动驾驶已完成源码实现；商业授权源码已支持同一安装包下的 9.9 元三次体验版与 49.9 元永久版，并保留单安装绑定和 24 小时在线租约。正式 Cloudflare 环境尚未应用本次 D1 迁移和 Worker 发布；下一步是部署后完成两种真实订单、真实任务与双平台发行验收。

## 产品定位

Lab Factory v2 是一个可靠的 DOCX 模板编译器：首次学习一门课程的模板结构、写作规则和用户偏好，之后在不破坏源文件和非目标区域的前提下，稳定生成位置正确、格式安全、风格有差异的实验报告草稿。

当前目标是支持首批 20 位付费用户。购买页负责创建订单和提交核验信息，收款核验、密钥发送与原路退款继续人工处理；账号系统、完整用户中心和自动支付暂不建设。

### 在线密钥付费内测

- 用户通过 `/buy` 创建带随机查询 Token 的订单；卖家人工核款后一次点击完成确认、签发和交付。订单 Token 只保存哈希，自动交付密钥按订单从卖家 Secret 确定性派生，D1 不保存明文。
- 订单支持等待付款、提交核验、确认/驳回、签发、交付、退款申请和退款完成，重复签发不会生成第二把密钥。
- 首个安装原子绑定密钥；第二个安装被拒绝。客户端启动时刷新，之后每 6 小时刷新 24 小时签名租约。
- 9.9 元体验密钥按稳定报告 ID 在服务端幂等记账，最多 3 个报告且拒绝 Skill 凝练；49.9 元永久密钥不限次数并解锁 Skill 凝练。旧密钥迁移后保持永久版权益。
- 数字化密钥交付后不提供自助无理由退款；重复付款、无法激活且无法修复或重大故障由售后人工处理，确认退款或违规封禁后停止续租。误封可恢复，换机可人工重置绑定。
- 在线租约私钥与正式离线许可证私钥严格分离；客户端只内置租约公钥。
- 用户明确同意后才在本机记录白名单使用事件；只有用户主动导出并发送时数据才离开设备。
- 更新由销售者人工发送安装包和 SHA-256，客户端不联网检查、不下载、不静默安装。
- 不处理共享电脑或完整克隆环境；商业表述仅承诺“一个密钥绑定一个安装”。

## 已实现

### v2.1 报告自动驾驶

- 新报告入口改为 `材料与模板 → 个性化确认 → 自动生成 → 最终验收 → Skill 学习摘要`，Skill 不再是用户必须先理解的入口。
- 新增 5 个 MCP 接口：prepare、answer questions、confirm checkpoint、advance 和 status。
- 保留 8 维稳定偏好作为用户可调层；优先从旧报告画像或系统 writer capsule 预填，不再强迫冷启动用户填写配置表；低风格置信度时按需触发两个短样例校准。
- 首次使用新增可选旧报告校准：可读取 1–3 份本人任意科目 DOCX/Markdown/文本报告，只在本地提取句段、术语、人称、连接词、列表和反思特征；画像不保存正文、源路径或个人信息，没有样本时不阻断。
- 冷启动不再让所有用户使用同一默认文风：按不含个人信息的安装身份生成稳定 writer capsule，叠加课程修正和单报告 seed；个人画像存在时优先覆盖相应稳定轴。
- 新增 `writer-genome-v3`、`variation-v3` 和 `generation-contract-v3`，把差异化从单一强调点扩展为 12 个稳定写作轴和报告级内容组织变化；宿主必须先建立事实账本再规划和生成。
- 新增领域化 humanization audit：成组检查意义拔高、宣传腔、模糊归因、否定式排比、机械连接词、万能结论和聊天机器人痕迹，保留课程术语、代码、公式、引用和必要技术表达；禁止新增事实、故意写错或使用 AI 检测器分数作为门禁。
- 新增本机历史/脱敏批次跨报告碰撞检查，输出不含比较正文和路径的连续文本、相似句、字符 5-gram 与可解释风格指纹结果。
- preflight 完整披露字体、字号、颜色、标题、段落、编号、表格、页眉页脚和图片关系的具体值及来源。
- 默认 `balanced` 模式正常任务只保留 preflight 和最终 DOCX 两个常规确认点；结构变化、低置信度定位、格式冲突和硬门禁才额外暂停。
- 2.1 会话实现状态版本、UUID 幂等缓存、一次性摘要确认 token、跨平台会话锁、原子 JSON 提交和只保存对象 ID 的隐私边界。
- 旧 v2.0 会话继续走 strict 流程；fast 枚举已保留但在完成 3 次无人协助试用前返回 `MODE_NOT_ENABLED`。

### DOCX 模板编译与安全写回

- 直接解析 DOCX OOXML inventory，覆盖正文、表格单元格、页眉页脚、样式、编号、上下文和图片关系。
- 为可写位置生成稳定 `node_id`，保存结构路径、表格行列坐标、上下文指纹和样式来源。
- 文本框、公式、域和修订等复杂对象标记为 `unsupported`，禁止静默写入。
- 保留精确模板指纹，并使用不含个人正文的 `family_signature` 对固定标签、页眉页脚、表格形状和容器分布进行兼容评分；局部内容增长不会直接判为新家族。
- Word `AlternateContent` 同时包含 Choice/Fallback 时只 inventory 主表示，避免文本框重复候选。
- `auto` 要求分数至少 0.90 且领先第二候选至少 0.15；`confirm` 必须由用户选择；`blocked` 禁止写入。
- 使用 `python-docx + lxml/OOXML` 最小修改生成副本，验证源文件不变及非目标 DOCX 部件哈希不变。
- 支持段落插入、占位符替换和表格单元格写入，并输出写入审计信息。
- inventory 输出可审阅 `heading_tree`，并解析 `styles.xml` 中自定义标题样式及 outline level。
- 支持 `section-plan.json` 受控扩展：宿主 AI 完整阅读材料后提出二/三级标题方案；引擎校验材料摘要、用户要求、父标题、插入范围、同级样式、编号和源文件哈希，用户确认后才写入副本。
- 已修复红色提示色继承、标题编号误继承、批量写入路径漂移，并把正文长度范围升级为写入前强制门禁。

### 受控工作流

- 已实现持久化状态机：

  ```text
  materials_scanned
  → requirements_confirmed
  → sections_resolved（可选；无需扩展时跳过）
  → placements_resolved
  → content_ready
  → draft_generated
  → draft_reviewed
  → finalized
  → iteration_decided
  ```

- 会话保存 `session-state.json` 和审计日志，可以在客户端中断后恢复。
- 需求未确认不得生成草稿；低置信度定位未解决不得写入；草稿未经用户审阅不得 Finalize。
- 草稿审阅记录 `review_id`、用户决定和反馈摘要。
- 终稿后提供继续修改、审阅 Skill 更新 diff、完成但不更新三个出口。
- Skill 更新经过隐私门禁，排除姓名、学号、样本正文、当前报告正文和一次性异常。

### 差异化与防照抄

- 支持课程写作画像、四维写作参数和预设。
- 支持不保存样本正文的 `style-card.json`。
- 每份报告保存 `variation_seed`，同一报告修改时保持风格稳定。
- Finalize 前执行连续重复文本、句子相似度和字符 5-gram 三类检查。
- 相似性门禁失败会阻止 Finalize，不允许 Agent 绕过。

### 接口、兼容与分发

- MCP Server 已升级为 v0.2.0，并提供 inventory、模板配置、定位确认、会话、草稿审阅、Finalize、写作画像、风格卡、v1 迁移和 Skill 更新接口。
- CLI 已增加对应 v2 命令。
- v1 Fill Map 仅保留读取和迁移能力；旧字符串锚点必须重新定位。
- 专属课程 Skill 脚手架、Schema、验证器、使用文档和 macOS/Windows 构建脚本已更新。

## 尚未完成或尚未证明

### 真实模板准确率

- 尚未建立至少 10 份脱敏真实 DOCX 的黄金测试集。
- 尚未人工标注正确写入节点和不可修改区域。
- 尚未校准定位评分和相似性阈值。
- 因此尚不能声称高置信度定位准确率达到 99%，也不能声称自动覆盖率达到 70–80%。

### WPS、Windows 与真实用户

- 尚未完成 Windows/macOS WPS 上至少 10 个真实模板的写入前后验收。
- 尚未完成 WPS 打开、保存、再次解析的往返测试。
- Windows 构建脚本已经更新，但尚未在 Windows 实机上构建和验证成品。
- 尚未完成 10–20 位用户的正式内测及任务指标收集。

### 差异化效果

- 写作画像、风格卡、变化种子和相似性门禁已经实现，但尚未完成多用户、多种子输出差异评测。
- writer capsule、旧报告画像、身份化去模板腔审计和跨报告碰撞门禁已有确定性源码回归，但尚未用同一 agent/model 完成 192 份校准集和 720 份发布级批量生成实验。
- 尚未证明最终输出在保持事实准确的同时足够不同。
- 风格卡由宿主 Codex/Claude Code 从参考材料生成；当前引擎负责 Schema 校验和正文泄漏拦截，不负责独立理解任意参考报告。

### 标题扩展剩余边界

- 已支持用户确认后二级/三级标题新增，但尚未完成多个不同老师模板、自动编号模板和 WPS 往返的规模化验证。
- 目录域不会自动刷新，新增或改名标题后仍需用户在 WPS 更新目录。
- 暂不支持一级标题、文本框中的标题、修订区标题、跨节复杂编号和无法识别样式的模板。
- AI 是否完整、准确理解课程任务仍需由需求复述和用户确认保证；确定性引擎只校验结构化方案，不替代宿主模型理解材料。

### 有意保留的安全边界

- 文本框、复杂公式、域、修订、部分浮动图片和复杂嵌套表格暂不自动写入。
- 视觉一致性仍需用户在最终使用的 Word/WPS 环境中确认。
- `docxtpl` 只用于 Lab Factory 控制的标准占位模板，不作为任意老师模板的默认引擎。

## 发布判断

当前可以作为内部开发版和受控测试版使用，但不应宣称已经达到生产级、支持所有复杂 DOCX，或已经满足 99% 定位准确率。进入下一发布阶段的前提是完成真实黄金测试集、WPS 双平台验收和真实用户指标收集。
