# Lab Factory 用户指南

## 生成报告

新任务默认使用“报告自动驾驶”：

1. 提供任务材料和 DOCX 模板。
2. 首次使用时可以额外提供 1–3 份自己以前完成的实验报告，任何科目均可。系统只在本地提取句段节奏、解释顺序、术语处理、人称和反思习惯，不保存或复制正文；没有时直接跳过。
3. 有旧报告画像时优先使用个人稳定习惯；没有时系统按当前安装分配一个稳定写作 capsule，避免不同用户都落到同一种默认风格。两种方式都可以在生成前摘要中调整。
4. 查看生成前摘要。系统会明确列出写作身份、报告级变化、结构原型（例如图先讲、文先讲、图文穿插、表格先行）、视觉密度、问题证据位置、去模板腔规则、字体、字号、行距、编号、表格等要求，以及它们的来源。
5. 确认后，明确且低风险的中间步骤会自动执行；只有结构变化、定位不确定或事实、写作身份、去模板腔、跨报告碰撞等安全检查失败时才会追加提问。
6. 在 WPS 或实际编辑器中检查最终 DOCX，这是正常流程的第二个确认点。
7. 最后可接受、修改或拒绝 Skill 学习摘要；旧报告和本次报告正文都不会进入个人画像或 Skill。

没有参考报告也可以继续。系统会使用 writer capsule 生成可解释的变化策略；画像置信度低或偏好冲突时才会给出两个短样例供选择。首次没有本机历史对照时，差异报告会明确标注“无基线”，不会假装已经证明与他人不同。系统不会用 AI 检测器分数判断报告是否合格，也不会通过故意加入错字或虚构经历来制造“学生感”。

需要后补的图、截图、绘图和表格会在草稿中提前登记为单独占位，例如 `【图 2-1：登录失败提示；待补：包含错误信息的真实界面截图】`。正文会直接写“如图 2-1 所示”，图和表分别编号。一个占位不会再同时要求多张图；类职责、数据库字段、测试用例、配置项或结果对比等适合行列表达的内容，会生成正式表格或有编号、有名称的表格占位。问题与解决办法若用截图更直观，会在问题后、问题与解决之间或解决后保留对应位置。

## 激活

安装包不区分版本，激活密钥决定能力：

- 9.9 元体验版：最多创建 3 个报告会话，不支持生成、凝练或更新专属 Skill；同一报告失败重试不重复扣次。
- 49.9 元永久版：报告次数不限，支持凝练和更新专属 Skill。

体验版次数保存在授权中控，创建新报告时需要联网；重装应用不会恢复次数。永久版继续支持最长 24 小时的本地租约离线窗口。

尚未购买时，从销售者公布的独立 `/buy` 页面创建订单。订单页不需要账号，也不会要求上传付款截图；请保存页面返回的订单查询 Token。

```bash
lab-factory activate-key '销售者提供的密钥' \
  --accept-terms-version 1.0 --confirm-age-18
lab-factory status
```

密钥首次使用后绑定当前安装。客户端每次启动尝试刷新授权，授权服务暂时不可达时可以继续使用尚未到期的本地租约，最长不超过 24 小时。

密钥属于数字化交付，交付后原则上不接受无理由退款。重复付款、无法激活且无法修复、重大功能缺陷或法律另有规定时，可查看售后指引：

```bash
lab-factory request-refund
```

该命令只显示售后联系方式，不会自动停用密钥或提交退款。请加入售后 QQ 群 923937311，提供订单号与问题描述；不要公开订单 Token 或激活密钥。退款经人工确认后，由销售者原路处理并封禁关联密钥。换机或应用数据丢失时联系销售者重置安装绑定。共享电脑或完整环境克隆不在授权保证范围内。

## 反馈

数据记录默认关闭。开启后也只保存在本机，不会自动上传：

```bash
lab-factory telemetry enable
lab-factory feedback review-001 --rating 4 --edit-time 15_30m --issue format
lab-factory feedback-export --output lab-factory-feedback.json
```

你可以先打开 JSON 检查，再主动发送到产品提示的反馈邮箱。`telemetry disable` 停止记录；`telemetry clear` 删除本地记录。

## 更新

更新由销售者人工发送。安装前校验其公布的 SHA-256：

```bash
lab-factory verify-update <安装包路径> --sha256 <64位校验值>
```

校验失败时不要安装。
