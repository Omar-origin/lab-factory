先看演示文件
准备材料安装与宿主激活生成与补图失败恢复与隐私

1. 准备一个任务文件夹

放入任务说明、原始 DOCX 模板、已完成的实验记录和真实截图。保留原文件，生成结果另存。没有完成的操作标记为待完成，不把示例数据当实验结果。

有自己以前的报告时，可额外提供 1–3 份用于提取写作习惯；没有也能继续。

2. 安装并连接宿主

从订单交付信息或销售者获取与你系统对应的安装包，核对交付方提供的 SHA-256。当前采用人工交付和更新。

Codex、Claude Code 可使用安装命令配置；WorkBuddy 或 Kimi CLI 使用本地 stdio MCP 配置，命令指向实际的 lab-factory 可执行文件，参数为 serve-mcp。配置导出支持 lab-factory export-config --client workbuddy 和 --client kimi。更换宿主后先确认它能列出 Lab Factory 工具。

普通网页聊天不一定能访问本地文件或执行工具。DeepSeek 等 API 模型需通过有本地工具执行能力的宿主；不能仅凭模型名称认定它能截图或编辑 Word。

3. 激活并检查状态

订单交付后在自己的终端激活，不把密钥发送给聊天模型：

lab-factory activate-key '你的密钥' --accept-terms-version 1.0 --confirm-age-18
lab-factory status

体验版按有效创建的报告会话计次，同一会话重试复用报告编号。激活或额度检查失败时，保留任务文件夹和会话编号后重试。

4. 给宿主这条指令

请用 Lab Factory 处理这个任务文件夹。先读取任务要求和 DOCX 模板，确认实际写入位置与格式；根据已有事实撰写报告。截图只能使用我提供的真实图片，表格用可编辑三线表。缺失材料明确列出。先给我生成前摘要，再生成副本，最后让我检查。

真实截图与三线表

支持原生图表的新版本通过 import_asset 登记 PNG/JPEG，再用 v3 内容包嵌入图片。表格由结构化行列数据生成，能在 Word/WPS 中编辑单元格；图注、表题和正文引用一起编号。模型不需要自己画三条线。

宿主没有截图权限时，自己截取所需步骤并放入任务文件夹。不要让模型补造“运行成功”截图。交付前打开 DOCX 检查图片、分页、表格、编号和事实；Word/WPS 具体版本仍需实际验证。

新能力需要包含 v3 工具的客户端；旧安装包请先向销售者确认更新。本站演示不代表你的安装包已经更新。

失败恢复与隐私

缺图或位置不确定：补充材料或确认位置后继续原会话。审核后改了文件：重新运行质量检查并确认新的文件，原审核不再有效。没有历史对照：允许首次生成，但不会宣称已证明与其他报告不同。

本地生成器不向商业授权网站上传报告正文。使用云端模型时，宿主发送的文本、图片或 OCR 可能进入该模型服务，请核对宿主的数据设置。课程 Skill 保存模板和规则，不能纳入报告正文或个人证据。

需要帮助时联系交付信息中的支持渠道，提供错误代码和会话编号，避免发送密钥和无关个人材料。
