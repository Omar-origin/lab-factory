# Lab Factory 改进设计与实施计划

日期：2026-09-13。状态：用户已认可总体改进方向；本轮完成设计存档与独立文档构件验证，尚未实现或部署下列主流程改造。此文档中的新增版本号、接口名、模块名均为提案，不代表已有可用命令。

依据：[2026-09-13 项目体检](../../../../reports/audit-2026-09-13/project-audit.md)。专项设计：[真实截图、原生三线表与多宿主兼容](2026-09-13-native-media-and-host-compatibility.md)。

## 1. 产品目标与验收边界

让用户提供课程任务、老师模板和真实材料后，得到事实可追溯、要求覆盖明确、图片位置正确、表格可编辑的 DOCX；减少人工返工和无意义确认，并使不同宿主下的机械排版质量保持一致。

分开报告四种结果：草稿可编辑、必需证据齐全、自动检查通过、目标编辑器人工验收通过。不得将任一单项直接等同于“可提交”。

保留模板保护、旧报告可选校准、稳定写作画像、同报告稳定 seed、失败可恢复和用户最终审阅。此次重点是修正质量判定并接通原生文档构件，不推倒现有引擎。

## 2. 用户流程

1. 检测宿主工具、可用模型能力、本地文件访问、截图权限与编辑器能力。
2. 读取课程材料和模板，展示已识别要求、可写区域、缺失证据和主要冲突。
3. 模型提出逐节写作计划与图表清单，工具校验任务覆盖和插入可行性。
4. 生成正文；已有设计信息直接生成表格，真实测量数据从材料或可复现执行结果读取。
5. 宿主在真实实验检查点获取截图，或用户选择已有图片；本地工具登记、匹配、插入。
6. 本地工具生成副本、检查真实 DOCX 与质量凭据的一致性、输出待办与预览。
7. 用户在实际 Word/WPS 环境审阅；终稿只使用与该次审阅一致的文件版本。
8. 用户选择继续修改、接受课程规则学习或完成但不学习。

正常流程尽量只有材料摘要与最终稿两个产品确认点。宿主自身的文件、电脑操作与工具权限提示独立存在，不承诺不同宿主都只有两次点击。

## 3. 工作包及依赖

| 工作包 | 具体交付 | 依赖 | 完成标准 |
|---|---|---|---|
| A 产物可信与终稿检查 | 产物登记、文件哈希、审计版本、统一 strict/balanced finalizer | 无 | 不存在/被修改/审计过期的文件被拒绝 |
| B 计次与恢复 | 前置输入检查、稳定 report_id、计次幂等与失败恢复记录 | 无，可与 A 分阶段实施 | 参数错误不计次，同报告重试不重复扣次，超时可对账 |
| C 原生图表与证据清单 | 图片、三线表、题注、引用、真实对象识别 | A 的产物契约 | 图片嵌入包内；表格可编辑；占位变实物后检查不退步 |
| D 内容覆盖和差异化 | 要求覆盖表、逐节论证计划、范围化相似检查 | A、C | 必需图种/章节不漏；固定模板不误判；差异有事实依据 |
| E 多宿主适配 | WorkBuddy/Kimi CLI 的 MCP 接入、API 工具适配和手工导入回退 | A、C 的公共接口 | 能力探测真实；工具结果格式错误可恢复；无视觉也能插已知图 |
| F 官网与上手 | 公开首页、真实示例、安装说明、首份报告指引、手机选择状态保留 | 可先做文档，演示案例依赖 C | 新访客不先陷入登录；安装目录有正文；能找到下一步 |
| G 输出验收 | 小样本对照、编辑器往返、实际宿主测试、用户修改时间 | A–F 的对应功能 | 按版本保存证据，缺项明确，不用源码测试代替成品体验 |

建议顺序：A/B → C 最小闭环 → E 基础接入 → D → G；F 的文档和公开入口可以提前做。首个可用增量是“读现有截图 → 插入模板副本 → 生成原生三线表 → 验收”。自动操作不同实验软件截图是下一增量。

## 4. 产物可信与状态

新增本地 artifact registry：artifact_id、relative_path、sha256、生成工具版本、源模板摘要、内容计划摘要、资产摘要、创建状态。路径只在获准工作目录解析；不依赖模型拼接任意路径。

检查报告引用 generated_sha256、requirement_revision、asset_manifest_sha256、policy_version、tool_version 和实际发现。独立校验器计算机械结果，模型提供的是语义判断及其来源，不接受一个 `status=pass` 代替证据。

最终审阅绑定产物摘要和检查摘要。审阅后文档、题注或图片变化即失效；重新生成预览与必要检查。异常恢复后也必须复核，不接受 `exception_resolved=true` 单独作为问题已解决证据。

## 5. 模板保全规则的调整

现有“非目标 ZIP 部件不变”不能原样用于图片插入。新增图片需要修改对应 story 的 .rels、新增 word/media 以及必要的 [Content_Types].xml 条目。

按本次操作生成精确变更清单：原有未使用资产不删除；原有关系不覆盖；新媒体只能是清单中已登记的哈希；所有 ID 唯一；已有 DOCX 部件除明确允许的部分外保持不变。不得笼统放行整个 word/ 目录。

写入采用临时副本、完整校验和原子提交；并发锁与幂等记录沿用现有机制。复杂文本框、修订、域、浮动图片及无法确定布局的区域先报告限制。

## 6. 内容质量与差异化

每个要求登记 requirement_id、原始材料位置、expected_artifact、完成位置、证据状态。图种枚举区分类图、活动图、状态图、截图和数据表；缺少必需类图时不能用流程图自动顶替。

逐节计划说明：论点、依据、论证顺序、图表用途、篇幅预算、保留术语和可变部分。先筛选符合课程和证据条件的布局，再用 seed 选择；不为了变化添加无用截图或虚构经历。

文字检查只比较可编辑/新写正文，排除固定模板、声明、课程指定内容、代码和合理引用。可比批次按照任务与模板家族组织。普通段落数量相同先提醒；高正文相似与其他证据共同命中才按策略阻断。

保留 12 个写作轴，暂不增加更多轴。默认只生成一个候选；明确碰撞或质量不足时对受影响章节生成少量候选，并以覆盖率、事实一致性、可读性和差异解释选优。

“去模板腔通过”不等同于事实或质量通过；增加生成过程用语泄漏、设计一致性、无来源经历和内容/图表不对应检查。

## 7. 计次设计

先完成参数、模板、模式、既有会话和本地可写性检查，再进入计费状态。会话 ID 与单次工具调用的幂等键分离；同一报告 prepare/apply/repair 共享 report_id。

建议采用短期额度预留 → 成功建立有效会话时提交 → 建立前失败释放，并持久化 reservation_id 与恢复记录。服务端与本地不能原子提交：使用 outbox/可重试提交并定期对账；无法联网不伪造扣次成功。具体“成功会话”仍沿用商品承诺的口径，不悄悄改成按下载或终稿收费。

## 8. 官网与首次使用

公开首页说明用途、输入条件、真实产物、人工边界和成本条件；案例提供原始材料范围、生成前后片段和可下载自建样稿。不得把自建演示宣传为客户案例。

使用文档包含：宿主选择、系统条件、安装、激活、示例材料、首条操作指令、补图流程、表格编辑、失败恢复和售后。把“Skill 凝练”解释为记住课程模板和规则。

账户面板按状态提供下一步。手机套餐选择后显示继续按钮/底部摘要；登录后恢复套餐与账单选项。核实线上/本地入口差异再发布。

## 9. 数据与隐私说明

本地生成器不向商业授权网站上传报告正文。使用云端模型的宿主时，发送给模型的正文、OCR 或图像可能进入该模型服务；不能宣传为“全部材料永不上云”。默认给模型必要的文本和资产元信息；发送原图进行视觉理解时明确展示接收服务并遵守用户授权。

本地资产登记保存来源和哈希用于恢复，不进入公共画像或课程 Skill；日志不写报告全文、秘密和不必要的绝对路径。仅为当前获准任务读取/截图，不持续采集整个桌面。

## 10. 测试及发布标准

- A：伪造/不存在对象、审计过期、审阅后文件变更、并发写入、重复调用、中断恢复。
- B：无效输入、禁用模式、会话冲突、网络超时、扣次成功但会话提交失败、同报告跨入口重试。
- C：正文/普通表格单元格内插图，三线表，宽图，竖图，透明图，长表，重复引用，章节编号，资产缺失/更换，保留模板复杂对象。
- D：要求类图却只有活动图、已知设计信息误留空表、不同正文同结构、相同模板不同正文、无来源总结。
- E：工具强/弱、视觉有/无、本地文件可达/不可达、外部审批拒绝、错误参数和会话中断。
- 编辑器：Windows Word、Windows WPS、macOS Word、macOS WPS 实际版本分别记录；每个目标打开→编辑一个表格单元格→保存副本→重新解析图片、关系、边框与题注。未测试的平台不写“已兼容”。
- 内容对照：3 类任务 × 3 种偏好 × 2 seed × 前后两版共 36 份，固定模型版本与材料；跨宿主兼容测试另计，不混淆归因。

建议放行条件：来源保护与审阅绑定无失败；必需构件覆盖率 100% 或明确阻断；无已知真实表格误判；目标编辑器往返保留可编辑对象；记录实际耗时、返工与误拦截。具体完成时间基于第一批真实模板结果再估计。
