# Lab Skill Factory

本 skill 是未来 MCP 工具的内置 skill。它不直接写实验报告，而是帮助用户根据课程材料定制“指定科目/指定模板”的实验报告专属 skill。

默认生成科目级或模板系列级 skill。当前实验编号只作为初始样例，除非用户明确要求一次性实验级 skill。

## 最简调用

```text
请使用这个 skill：
<lab-skill-factory 路径>

根据这个实验报告/材料，帮我定制一个专属实验报告 skill：
<材料路径>
```

## v2 关键产物

- `skill-spec.md`：用户确认的专属 skill 规则。
- 专属 `SKILL.md`：由 MCP 内置生成器生成；开发环境可用 `skill-creator` 做质量参考。
- `requirements-summary.json`：从材料抽取并经用户确认的要求、格式、工具、证据和提交规则。
- `section-plan.json`：材料需要的章节与模板标题树之间的受控扩展方案；只有用户确认后才能在副本中新增二级/三级标题。
- `template-profile.json`：课程模板的 OOXML 结构定位、表格坐标、上下文和样式来源。
- `content-package.json`：宿主模型生成的字段化内容和经用户确认的低置信度节点。
- `personal-writing-profile.json`：可选从 1–3 份本人旧实验报告本地提取的基础写作画像；不含正文、路径和个人信息。
- `writing-profile.json` / `style-card.json`：课程写作画像和不含样本正文的风格特征。
- `writer-genome-v3.json`：按个人画像或安装 capsule 生成的稳定写作身份，控制 12 个可观察轴。
- `variation-v3.json`：在稳定身份附近变化的单报告解释、证据编排、图表位置和小结形态契约。
- `generation-contract-v3.json`：宿主必须执行的事实账本、结构/图表登记、规划、身份化去模板腔编辑和质量门禁顺序。
- `humanization-audit.json` / `document-structure-audit.json` / `diversity-report.json`：领域化 AI 模板腔审计、编号与交叉引用审计，以及本机历史/脱敏批次的文字和结构流碰撞检查；不使用 AI 检测器分数。
- `session-state.json`：可以跨客户端重启恢复的强制工作流状态。

v1 的 `fill.md + fill-map.json` 只用于读取和迁移；新任务不得继续创建字符串首命中式写入。

## 核心原则

- MCP 工具是 skill factory，不是代写器。
- 专属 skill 先输出预览和映射，再由用户确认。
- 第一次默认只填补，不删改原文；模板标题不足时，允许在完整阅读材料并经用户确认 `section-plan` 后新增二级/三级标题。
- 生成前先从头到尾完整阅读并理解用户已给的模板、任务书和文末提交说明，复述实验目标、任务步骤、填写范围、不可触碰区域、工具环境、截图来源、提交清单和缺失材料；用户确认理解无误后，再请用户补充材料并根据模板用通俗问题多轮确认需求。
- 必须确认必用工具、运行环境、源码/Notebook、系统地址、截图来源、提交清单、压缩包格式和命名规则。
- 每个阶段都请用户检查并鼓励修正 AI。
- 截图和绘图只能来自真实运行、用户材料或可复现代码输出；缺失时只留占位，不使用生图伪造截图。
- 图片、截图、绘图和表格必须单项占位，提前确定图/表编号、名称、补充要求和正文交叉引用；图与表分别编号。存在类职责、字段、测试用例、配置项、输入输出、异常或结果对比时，必须记录表格取舍，不能让所有证据都退化成长段落。
- 同一模板批次不仅要改变内容，还要按每报告 seed 改变图先讲/文先讲/图文穿插/表格先行/混合证据、视觉密度、问题证据位置和小结形态；结构流高度碰撞时不得 Finalize。
- 生成前根据模板多轮确认写作规范、内容粒度、实验小结结构和不可触碰区域；需求不清晰时继续追问。
- 用户选择默认时，把内置默认值当成本次用户要求展开写入 spec，而不是只记录“使用默认”。
- 默认格式包含一级/二级/三级标题样式，正文默认小四、黑色、中文宋体/英文 Times New Roman、首行缩进默认度量值 2；正文说明点约 150-200 字，实验小结每点约 100 字。
- DOCX/MD 先字节级复制，再按锚点填补，并继承目标样式。
- DOCX 默认使用 `python-docx + lxml`；`docxtpl` 只用于受控占位符模板，`Mammoth` 只用于辅助抽取，`pywin32 COM` 只作为 Windows + Microsoft Word 可选增强。
- 草稿阶段除用户确认的标题扩展外，默认不改变原文结构、字体、字号、内容、格式和排版。
- 草稿输出后先让用户检查；没问题但需要插图/截图/数据时暂停等待，用户回来后再二次修改、清理确认可删内容、添加免责声明、询问文件命名并输出最终版。
- 正式完成一次报告后询问是否受控迭代 skill，用户确认后才更新，并支持回滚。
