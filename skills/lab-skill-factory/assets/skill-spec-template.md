## 写作规范

- 语言：根据任务书、模板和用户确认决定；未明确时默认中文。
- 正文字体：默认中文宋体，英文 Times New Roman；除任务书、模板、评分标准或用户明确要求外，不使用其他字体。
- 正文字号：默认小四。
- 正文颜色：默认黑色。
- 正文首行缩进：默认度量值 2。
- 行间距：继承模板正文样式；无法判断时继续追问，用户选择默认后展开默认值。
- 一级标题：三号，中文宋体，英文 Times New Roman，居中，序号和文字之间一个半角空格，单倍行距，段前 3 行，段后 2 行。
- 二级标题：不缩进，左对齐，小三号，中文宋体，英文 Times New Roman，序号和文字之间一个半角空格，1.5 倍行距，段前 1 行，段后 0.5 行。
- 三级标题：序号缩进两个字符，四号，中文宋体，英文 Times New Roman，序号和文字之间一个半角空格，1.5 倍行距，段前 0.5 行，段后 0 行。
- 图题/表题：优先继承模板已有样式；未明确时继续追问，用户选择默认后展开默认值。
- 表格样式：优先继承模板已有表格样式。
- 页边距/页眉页脚：保留模板原样。
- 未明确项处理：必须继续追问；用户选择默认时，使用 `references/default-writing-parameters.md` 并把具体默认值展开为本次要求，来源标注 `default_confirmed`。

## 内容粒度要求

- 实验目的：按任务书和模板推断，生成前询问用户是否有字数要求。
- 实验环境：按用户提供环境填写；未提供且必须明确时再问。
- 实验步骤：按任务书和模板分点填写。
- 结果/分析：正文解释说明性质的小点尽量控制在 150-200 字左右。
- 实验小结：如模板存在实验小结，则按模板栏目分点；常见“问题和解决办法、心得体会、意见与建议”结构按每栏 3 小点处理。
- 截图前后说明：每个截图占位给出必要说明，普通说明点约 150-200 字。
- 表格说明：按模板需要补充，普通说明点约 150-200 字。
- 未明确项处理：必须继续追问；用户选择默认时，正文解释说明小点约 150-200 字；实验小结按栏目分点；若包含“问题和解决办法、心得体会、意见与建议”，则每栏 3 小点，每小点约 100 字，来源标注 `default_confirmed`。

## DOCX 工具策略

- 默认 DOCX 编辑工具：`python-docx + lxml`。
- 默认操作方式：字节级复制原文件后，在副本上按锚点做最小范围填补。
- 样式策略：新增段落、run 和表格内容继承目标锚点附近样式。
- `docxtpl` 使用条件：仅当模板是用户确认的受控占位符模板。
- `Mammoth` 使用条件：仅用于辅助抽取文档内容，不写回 DOCX。
- `pywin32 COM` 使用条件：仅 Windows + Microsoft Word 环境可选，不作为 Mac 默认依赖。
- 失败处理：无法可靠保真时，输出人工插入提示，不整篇重建。

## 格式保全策略

- 原文件只读，先做字节级副本，再修改副本。
- DOCX 不整篇重建，不用 Markdown 转 DOCX 覆盖原文档。
- 新增内容继承目标锚点所在段落、表格单元格或相邻正文样式。
- 无法可靠继承格式时，停止并提示用户。
- 第一次草稿只填补，不删除、不重排、不覆盖原文。
- 文档原本结构、字体、字号、颜色、段落、分页、目录、表格布局和已有内容默认全部锁定。

## fill-map.json 规则

每段 fill 内容必须映射到模板锚点。默认 `preserve_original: true`。

顶层必须包含：

- `copy_mode: "byte_for_byte_first"`
- `format_strategy: "inherit_target_anchor"`

每个 item 必须包含：

- `format_strategy: "inherit_target_anchor"`

## 截图和绘图占位规则

- 不生成虚假图片。
- 不复用参考案例截图。
- 不使用生图能力伪造 Notebook、软件界面、浏览器、设备或实验现场截图。
- 使用 `【截图：...】` 或 `【绘图：...】` 标注位置和操作提示。

## 草稿流程

1. 生成 `fill.md`。
2. 生成 `fill-map.json`。
3. 用户确认。
4. 字节级复制原文件。
5. 按锚点填入副本，新增内容继承目标样式。
6. 输出草稿。
7. 询问用户：`请查看，草稿是否可以？是否存在什么问题？有哪些需要修改的地方？`
8. 用户指出问题时，先修正新增内容、占位、`fill.md` 或 `fill-map.json`，再请用户检查。
9. 用户确认草稿没问题但仍需插入图片/截图/数据时，暂停等待用户完成，并提醒用户回来进行第二次修改。

## Finalize 流程

1. 用户补齐截图/绘图/数据后回来确认进入第二次修改。
2. 用户确认删除项、必须保留项和排版问题。
3. 用户提供封面个人信息。
4. 用户确认文件命名方式。
5. 调整排版，删除用户确认可删的模板提示、占位和草稿提示。
6. 在报告最后添加免责声明。
7. 生成最终版。
8. 用户确认最终版后，询问是否要受控迭代 skill；先说明拟更新方向，用户确认后才写入。

- 生成前完整浏览模板/任务书，包括末尾提交说明、命名规则和源码/Notebook 提交要求。
