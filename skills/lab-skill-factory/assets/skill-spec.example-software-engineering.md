# 软件工程实验八-软件部署和维护 实验报告 Skill Spec

## 目标

为软件工程课程实验报告定制一个本地实验报告专属 skill。当前实验八仅作为初始样例。

## 适配层级

- 默认层级：科目级/模板系列级
- 当前实验编号：实验八，仅作为初始样例
- 是否允许实验级：否，除非用户后续明确要求

## 适配范围

- 课程/科目：软件工程
- 实验类型：软件工程文档类实验
- 模板类型：软件工程课程实验报告模板
- 适用文件格式：docx
- 当前样例实验：实验八-软件部署和维护
- 后续可适配实验：同课程、同模板系列的其他实验
- 不适用场景：非软件工程课程模板

## 触发词

- 软件工程实验报告
- 做软工实验
- 软件工程实验N

## 输入材料

- 实验任务书：用户提供
- 实验报告模板：用户提供
- 同科目参考案例：可选，仅参考格式
- 评分标准：可选
- 数据/源码/截图：可选
- 必用工具/环境：浏览器、自选软件系统或本地/线上可访问地址
- 提交说明/命名规则：按任务书或用户后续确认

## 文档理解与任务复述

- 已完整阅读的材料：实验任务书、实验报告模板、用户提供的截图/系统材料和可选参考案例
- 实验目标：围绕软件部署和维护实验，整理系统部署、运行访问、维护说明、截图证据和实验小结
- 需要完成的任务：确认自选系统，补充报告正文空白，准备真实系统截图占位，完成实验小结
- 报告模板结构：封面、目录、说明页、正文实验内容、实验小结、教师评语/考核区域
- 需要填写的区域：用户确认的正文空白区域、实验小结区域、截图占位区域
- 不可触碰的区域：封面原结构、目录、说明页、教师评语、考核结果、已有正文
- 必用工具/运行环境：浏览器、自选软件系统、本地地址/线上地址/GitHub 仓库
- 源码/Notebook/数据：默认不要求 Notebook；如任务书要求源码或仓库，需单独确认
- 截图和图表来源：真实系统页面、真实浏览器访问结果或用户提供截图
- 提交清单和命名规则：按任务书或用户 finalize 前确认
- 文末、附录、标红提醒或容易漏掉的要求：提交说明、命名规则和个人信息字段需在 finalize 前再次确认
- 用户确认情况：待用户确认后才能生成专属 skill

## 需求确认清单

- 适配层级：
  - 采用规则：科目级/模板系列级，实验八仅作为初始样例。
  - 来源：confirmed_by_user
  - 依据：用户要求该 skill 适用于软件工程科目的所有实验报告。
- 填写区域：
  - 采用规则：只填写模板占位、正文空白、用户确认的实验小结和截图占位。
  - 来源：derived_from_template
  - 依据：实验报告模板中的正文占位和实验小结栏目。
- 不可触碰区域：
  - 采用规则：封面原结构、目录、说明页、考核结果、教师评语和用户未确认章节保持不动。
  - 来源：derived_from_template
  - 依据：模板固定区域。
- 写作规范：
  - 采用规则：标题使用默认一级/二级/三级格式；正文默认小四、中文宋体、英文 Times New Roman、黑色，首行缩进默认度量值 2，不使用其他字体或颜色；表格、页眉页脚优先继承模板样式。
  - 来源：default_confirmed
  - 依据：用户未提供额外格式要求时采用 `references/default-writing-parameters.md`。
- 内容粒度：
  - 采用规则：正文解释说明性质的小点约 150-200 字；正文按模板章节分点填写。
  - 来源：default_confirmed
  - 依据：`references/default-writing-parameters.md`。
- 实验小结：
  - 采用规则：按“问题和解决办法、心得体会、意见与建议”三栏写；每栏 3 小点，每点约 100 字。
  - 来源：default_confirmed
  - 依据：`references/default-writing-parameters.md`。
- 截图/绘图/真实数据：
  - 采用规则：用户未提供真实材料时只留占位和操作提示。
  - 来源：derived_from_template
  - 依据：模板实验内容和截图需求。
- 工具环境与提交要求：
  - 采用规则：软件工程实验需要确认用户自选系统、浏览地址或 GitHub 仓库；报告截图必须来自真实系统页面或用户提供截图；最终提交命名按任务书或用户 finalize 前确认。
  - 来源：derived_from_template
  - 依据：软件工程部署和维护类实验通常依赖真实系统环境与截图。
- 草稿与 finalize 边界：
  - 采用规则：草稿阶段只填补不删除；删除模板提示、填写封面个人信息和最终命名放到 finalize 前确认。
  - 来源：derived_from_template
  - 依据：factory 固定填补式流程。

## 需要填写的区域

- 用户确认的正文空白区域
- 用户确认的实验小结区域
- 用户确认的截图占位区域

## 不可触碰的区域

- 封面原结构
- 目录
- 说明页
- 教师评语
- 用户未确认的章节
- 模板里已有内容

## 写作规范

- 语言：中文
- 正文字体：默认中文宋体，英文 Times New Roman；除任务书、模板、评分标准或用户明确要求外，不使用其他字体
- 正文字号：默认小四
- 正文颜色：默认黑色
- 正文首行缩进：默认度量值 2
- 行间距：继承模板正文样式；无法判断时继续追问，用户选择默认后展开默认值
- 一级标题：三号，中文宋体，英文 Times New Roman，居中，序号和文字之间一个半角空格，单倍行距，段前 3 行，段后 2 行
- 二级标题：不缩进，左对齐，小三号，中文宋体，英文 Times New Roman，序号和文字之间一个半角空格，1.5 倍行距，段前 1 行，段后 0.5 行
- 三级标题：序号缩进两个字符，四号，中文宋体，英文 Times New Roman，序号和文字之间一个半角空格，1.5 倍行距，段前 0.5 行，段后 0 行
- 图题/表题：使用模板已有样式
- 表格样式：使用模板已有样式
- 页边距/页眉页脚：保留模板原样
- 未明确项处理：必须继续追问；用户选择默认时，使用 `references/default-writing-parameters.md` 并把具体值展开为本次要求

## 内容粒度要求

- 实验目的：按任务书和模板推断，生成前需用户确认
- 实验环境：按用户提供环境填写，未提供则留待办
- 实验步骤：按任务书分点
- 结果/分析：结合用户材料，不能伪造真实结果；正文解释说明小点约 150-200 字
- 实验小结：默认分为问题和解决办法、心得体会、意见与建议；问题和解决办法写 3 个问题，心得体会和意见与建议各写 3 个小点
- 截图前后说明：每个截图占位给出插入提示，普通说明点约 150-200 字
- 表格说明：按模板需要补充，普通说明点约 150-200 字
- 未明确项处理：必须继续追问；用户选择默认时，正文说明点约 150-200 字；实验小结每栏 3 小点，每个小点约 100 字

## DOCX 工具策略

- 默认 DOCX 编辑工具：`python-docx + lxml`
- 默认操作方式：字节级复制原文件后，在副本上按锚点做最小范围填补
- 样式策略：新增段落、run 和表格内容继承目标锚点附近样式
- `docxtpl` 使用条件：仅当模板是用户确认的受控占位符模板
- `Mammoth` 使用条件：仅用于辅助抽取文档内容，不写回 DOCX
- `pywin32 COM` 使用条件：仅 Windows + Microsoft Word 环境可选，不作为 Mac 默认依赖
- 失败处理：无法可靠保真时，输出人工插入提示，不整篇重建

## 工具环境与提交要求

- 必用工具/平台：浏览器、自选软件系统或代码仓库
- 运行环境：用户提供本地地址、线上地址或 GitHub 仓库；未提供则留占位并追问
- 源码/Notebook 产物：软件工程实验默认不要求 Notebook；如任务书要求源码或仓库，必须单独确认
- 数据集/输入材料：按用户系统实际材料
- 截图来源：真实系统页面、真实浏览器访问结果或用户提供截图；不使用生图伪造界面
- 报告外需提交文件：按任务书或用户后续确认
- 压缩包格式：按任务书或用户后续确认
- 命名规则：按任务书或 finalize 前用户确认
- 后置到 finalize 确认的个人信息：姓名、学号、班级、序号

## 格式保全策略

- 原文件只读，先做字节级副本，再修改副本。
- DOCX 不整篇重建，不用 Markdown 转 DOCX 覆盖原文档。
- 新增内容继承目标锚点所在段落、表格单元格或相邻正文样式。
- 无法可靠继承格式时，停止并提示用户。
- 第一次草稿只填补，不删除、不重排、不覆盖原文。
- 文档原本结构、字体、字号、颜色、段落、分页、目录、表格布局和已有内容默认全部锁定。

## 参考案例使用边界

参考案例仅用于学习格式、栏目、图文关系、截图位置和详略程度。不得复制正文、数据、截图、结论、个人信息或独特表达。

## fill.md 结构

```markdown
# <实验名称> 填补内容预览

## 文档理解与任务复述

## 填写范围
## 不可触碰范围
## 写作规范确认
## 内容粒度确认
## 工具环境与提交确认
## 正文内容
## 表格内容
## 实验小结

默认按模板栏目分点。若包含“问题和解决办法、心得体会、意见与建议”：

- 问题和解决办法：写 3 个问题，格式 `问题1：xxx。解决办法：xxx。`
- 心得体会：写 3 个小点。
- 意见与建议：写 3 个小点。
- 每个小点尽量控制在 100 字左右。
## 截图/绘图占位
## 用户待办
```

## fill-map.json 规则

每段 fill 内容必须映射到模板锚点。默认 `preserve_original: true`。顶层必须包含 `copy_mode: "byte_for_byte_first"` 和 `format_strategy: "inherit_target_anchor"`。

## 截图和绘图占位规则

- 不生成虚假图片。
- 不复用参考案例截图。
- 不使用生图能力伪造 Notebook、软件界面、浏览器、设备或实验现场截图。
- 使用 `【截图：...】` 标注位置和操作提示。

## 草稿流程

1. 生成 `fill.md`。
2. 生成 `fill-map.json`。
3. 用户确认。
4. 字节级复制原文件。
5. 按锚点填入副本，新增内容继承目标样式。
6. 输出草稿。
7. 询问用户：`请查看，草稿是否可以？是否存在什么问题？有哪些需要修改的地方？`
8. 用户指出问题时，先修正新增内容、占位、`fill.md` 或 `fill-map.json`，再请用户检查。
9. 用户确认草稿没问题但仍需插入图片/截图/数据时，暂停等待用户完成，并提醒用户回来进行第二次修改。

## Finalize 流程

1. 用户补齐截图/绘图/数据后回来确认进入第二次修改。
2. 用户确认删除项、必须保留项和排版问题。
3. 用户提供封面个人信息。
4. 用户确认文件命名方式。
5. 调整排版，删除用户确认可删的模板提示、占位和草稿提示。
6. 在报告最后添加免责声明。
7. 生成最终版。
8. 用户确认最终版后，询问是否要受控迭代 skill；先说明拟更新方向，用户确认后才写入。

## 合规边界

- 不伪造真实实验数据。
- 参考示例必须标注参考性质。
- 不保存用户隐私到 skill。
- 生成内容仅供学习参考，需用户核验。

## 版本与迭代

- 初始版本：0.1.0
- 更新方式：用户满意后生成拟更新摘要，用户确认后写入。
- 回滚方式：保留旧版本。

## 验收测试

- 能生成 `fill.md`。
- 能生成 `fill-map.json`。
- 默认科目级/模板系列级，不圈死单个实验编号。
- 生成前从头到尾完整理解文档，并复述任务要求让用户确认。
- DOCX 工具策略正确：默认 `python-docx + lxml`；`docxtpl`、`Mammoth`、`pywin32 COM` 只作为条件增强。
- 写作规范和内容粒度已确认；用户选择默认时已展开为具体执行规则。
- 生成前完整浏览模板/任务书，包括末尾提交说明、命名规则和源码/Notebook 提交要求。
- 必用工具、运行环境、源码/Notebook、系统地址、截图来源和提交产物已确认。
- 草稿阶段不删除原文。
- 草稿阶段不破坏 DOCX 结构、排版、字体、字号、表格样式和已有内容。
- 截图/绘图只来自真实运行、用户材料或可复现代码输出；缺失时只占位。
- 参考案例不被复制。
- Finalize 前确认删除项和封面命名。
