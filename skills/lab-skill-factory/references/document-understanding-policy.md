# Document Understanding Policy

## 核心要求

“浏览文档”不等于“理解任务”。在生成 `skill-spec.md`、专属 skill、`fill.md` 或草稿前，必须先完成文档理解门禁。

门禁包含三步：

1. 从头到尾完整阅读用户提供的每份模板、任务书、评分标准、提交说明和参考材料。
2. 提炼并复述任务要求，证明已经理解文档。
3. 等用户确认理解无误后，再进入下一步。

不能只看标题、目录、前几页、关键词命中段落或脚本摘要。脚本只能辅助定位，不能替代完整阅读和理解。

## 必须复述的内容

复述时使用用户能看懂的话，至少覆盖：

- 实验名称、课程/科目、当前实验编号和适配范围。
- 实验目的：这次实验要解决什么问题、验证什么知识点。
- 实验任务：用户实际要做哪些步骤、写哪些内容、完成哪些操作。
- 报告结构：模板有哪些章节、哪些区域需要填写、哪些区域必须保留。
- 写作规范：字体、字号、颜色、行距、标题、表格、图题、页眉页脚等要求。
- 内容粒度：每部分大致写多少、是否分点、实验小结怎么写。
- 工具环境：必须使用的软件、Notebook、代码环境、系统地址、仓库、数据集或运行平台。
- 证据来源：截图、图表、代码、运行结果、数据和图片应来自哪里。
- 提交要求：报告、源码、Notebook、数据、压缩包、文件命名和个人信息字段。
- 风险和缺口：哪些材料缺失，哪些必须由用户补充，哪些只能留占位。

## 复述格式

建议使用：

```markdown
## 我对任务的理解

- 实验目标：
- 需要完成的任务：
- 需要填写的报告区域：
- 不能动的原文区域：
- 必须使用的工具/环境：
- 需要的源码/Notebook/数据：
- 截图和图表来源：
- 写作和格式要求：
- 提交清单和命名规则：
- 目前还缺的材料或需要你确认的点：

请查看，我这样理解是否准确？有没有漏掉或误解的要求？
```

如果用户指出理解错误，必须先修正复述，再继续。不能一边保留错误理解一边生成 skill 或报告。

## 对生成出来的专属 skill 的要求

专属 skill 每次处理新的实验报告时，也必须执行同样门禁：

- 先完整阅读用户当次提供的报告模板、任务书和材料。
- 先复述任务要求和缺口。
- 用户确认后，才生成 `fill.md + fill-map.json`。

如果用户只给了一个文档路径，专属 skill 也不能直接填报告。它必须先读完整个文档并复述任务要求。
