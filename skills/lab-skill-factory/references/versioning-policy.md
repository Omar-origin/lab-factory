# Versioning Policy

## 版本号

专属 skill 使用语义化版本：

```text
0.1.0 初始可用版本
0.1.1 小规则修正
0.2.0 新增模板或流程能力
1.0.0 稳定可复用版本
```

## 受控迭代

不要让 skill 自动改自己。

正式完成一次实验报告后，专属 skill 必须主动询问用户是否要更新迭代，但不能自动写入。

询问方式要通俗：

```text
这次报告已经完成了。要不要把这次流程里有用的经验更新到这个专属 skill 里？我可以先列出准备优化的方向，你确认后再改。
```

更新流程：

1. 完成一次报告。
2. 请用户检查最终报告是否满意，并询问哪些地方做得不好。
3. 专属 skill 总结本次流程：哪些规则有效、哪里出错、哪些格式/锚点/字数/截图/finalize 流程需要优化。
4. 询问用户是否要更新迭代 skill，并说明拟更新方向。
5. 专属 skill 输出拟更新摘要。
6. 用户确认。
7. MCP 写入新版本。
8. 更新日志。
9. 保留回滚点。

## 更新摘要

更新摘要必须包含：

- 新增规则。
- 修改规则。
- 修正的错误。
- 本次报告流程中吸取的经验。
- 不应泛化的特殊情况。
- 是否涉及格式、锚点、截图、finalize。
- 隐私检查结果。

## 公共规则和个人规则分离

公共规则可以来自远程规则库或产品更新。

个人规则只来自用户确认，不被公共更新覆盖。

合并冲突时，先展示差异，让用户选择。
