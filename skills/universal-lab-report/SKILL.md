# 通用实验报告 Skill

## 目标

帮助用户把实验任务书、模板、样例、原始数据、源码、截图、课件等材料整理成实验报告草稿，并在用户补齐必要证据后生成最终版。这个 skill 的定位是学习辅导和参考整理，不是替用户伪造实验事实。

MCP 包装不是本阶段目标。本 skill 先作为可独立运行的工作流规范，后续可以被 MCP、Codex Skills、Claude Skills 或其他 agent 环境包装。

## 最高优先级规则

- 先完整复制源材料到输出工作区，再处理副本；不要直接修改用户原始文件。
- 调用 skill 后不要立刻开始写报告。先清点材料，再按一问一答方式引导用户确认关键写作需求、格式要求和是否有参考案例；不要一次性抛出一大堆问题。
- 个人信息、详细环境版本等非当前阶段必须项可以提示用户稍后回答。实验环境默认按本机执行记录；只有运行、截图、数据解释或报告正文必须明确环境时，才再次追问。
- 开始填补内容前，必须先查看任务书、模板或报告原文，明确实验要求、需要使用的环境和工具，并向用户确认“哪些部分需要填写”。没有被任务书要求、模板占位标明或用户确认的地方，绝对不能动。
- 根据实验要求识别出的环境和工具，要主动询问用户实际使用哪些版本、软件、平台、数据文件或运行环境；后续执行、截图、文字描述和用户指导都按用户确认的环境工具来写。
- 任务书优先，其次是报告模板、评分标准、输出要求、原始数据、成品样例、课件和其他材料。
- 报告模板控制结构、封面、表格和排版；成品样例只用于判断完整度、老师偏好和常见章节，不照抄段落、数据、截图、个人信息或独特结构。
- 如果用户提供同科目参考案例，即使不是同一个实验，也只学习排版、栏目、图文关系、详略程度和常见填写方式，不复制其正文、数据、截图或个人信息。
- 默认使用占位引导模式。不能证明为用户真实实验结果的内容，不要伪装成真实实测。
- 用户显式选择参考示例模式时，正文也要标注参考性质，并提醒用户核验。
- 需要截图时，先判断是否能从已有图片、可运行文件、日志、图表或最小复现中得到截图；不适合复现时留下清晰截图提示。
- 草稿版不能删除、改写或覆盖原实验报告/模板里已有的任何内容；即使原文写着“可删除”“填写后删除”，也要先保留并提示用户。只有用户补图等操作完成后，明确确认哪些内容要删除，才能在最终版中删除并调整排版。
- 草稿生成必须按模板锚点插入或替换占位附近内容，不要从零重建文档，不要把整篇报告塞进一个表格单元格，不要新建重复章节标题。已有“实验小结”标题时，只能在该标题后插入小结内容。
- 草稿版可以保留截图提示、用户待办、参考标注和缺失项；最终版只能在用户确认后生成，并按用户确认清理不该提交的提示文字。
- 用户确认已完成实验、已补齐截图或要求最终整理时，要根据封面页和模板字段询问需要填写的个人信息，并确认文件命名方式，再帮助用户填写封面和重命名输出文档。
- 文档末尾固定附免责声明：生成内容仅供学习参考，使用者需自行核验并遵守课程要求和学术规范。
- 完成一次报告后询问用户是否满意；用户满意后，才询问是否生成或更新单用户专属科目 skill。
- 专属科目 skill 只沉淀流程规则和格式偏好，不保存姓名、学号、账号、密码、完整报告正文或敏感材料。

## 工作流入口

用户可能提供任意路径，也可能提供标准输入文件夹。先按 `references/input-handling.md` 清点材料，然后进入 `references/workflow.md`。不要因为用户说“直接帮我完成”就跳过需求澄清阶段。

标准输入文件夹可包含：

- `实验任务书/`
- `实验所需文件/`
- `实验报告模板/`
- `成品实验报告/`
- `实验相关课件/`
- `实验原始数据.md`
- `个人信息.md`
- `评分标准.md`
- `输出文件要求.md`
- `目标写作风格.md`

任意路径输入也要支持。不要要求用户必须改成标准文件夹；可以在内部把材料角色识别清楚。

## 何时读取哪些 reference

- 开始任何实验报告任务：读取 `references/workflow.md` 和 `references/input-handling.md`。
- 需求确认和用户提问：读取 `references/interaction-policy.md`。
- 处理 DOCX、Markdown、模板、格式、字体、图注、免责声明：读取 `references/format-policy.md`。
- 处理模板锚点、原文保全、DOCX 插入位置、实验小结位置：读取 `references/template-editing-policy.md`。
- 需要理解为什么科目专属 skill 更稳定、需要提炼课程适配器规则：读取 `references/subject-skill-patterns.md`。
- 缺少真实数据、用户要求参考示例、需要判断合规边界：读取 `references/evidence-policy.md`。
- 任务书或模板要求截图、界面、运行结果图、仪器图、流程图：读取 `references/screenshot-policy.md`。
- 用户补齐材料并要求生成提交前版本：读取 `references/finalize-policy.md`。
- 报告完成后用户满意，或用户要求沉淀某门课流程：读取 `references/custom-skill-policy.md`。

## 推荐脚本

脚本都是辅助检查，不能替代人工判断：

- `scripts/inspect_inputs.py <paths...>`：清点输入材料并推测角色。
- `scripts/check_placeholders.py <files...>`：检查占位、用户待办和参考标注残留。
- `scripts/check_docx_basic.py <report.docx>`：检查 DOCX 是否可读、段落/表格/图片/占位数量。
- `scripts/compare_docx_preservation.py <source.docx> <draft.docx>`：检查草稿是否丢失源模板关键文本。
- `scripts/check_latex_literals.py <files...>`：检查 Markdown 或 DOCX 里是否残留原始 LaTeX 标记。

## 输出约定

每次任务至少说明：

- 输出工作区路径。
- 草稿版报告路径。
- 最终版报告路径，如果已经 finalize。
- 仍需用户完成的截图、数据、个人信息或外部操作。
- 已确认的实验要求、需填写范围、不可触碰范围。
- 已确认的实验环境、工具、版本、平台或数据文件。
- 已确认或采用默认值的写作/排版要求。
- 是否使用了同科目参考案例，以及只参考了哪些非内容性规则。
- 草稿中保留的原始提示、可删文字或模板说明，等待用户 finalize 前确认是否删除。
- 使用的数据模式：真实数据、参考示例、占位引导，或混合模式。
- 验证摘要：源文件是否未修改、占位是否合理、免责声明是否存在、格式风险。

## 完成后的询问

报告交付后，用简洁问题询问：

1. 用户是否已经完成实验、补齐截图/数据，并需要最终整理。
2. 如果需要最终整理，询问封面所需个人信息和文件命名方式。
3. 最终版交付后，询问用户是否满意这次报告结果。
4. 若满意，是否要把本次流程沉淀成单用户专属科目 skill。
5. 若用户同意，先输出拟沉淀规则摘要，等待确认后再写入或更新 skill。
