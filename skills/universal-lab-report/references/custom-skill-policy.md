# Custom Subject Skill Policy

## 目的

当用户对一次实验报告结果满意时，把这次可复用的流程经验沉淀为单用户专属科目 skill。专属 skill 用于同一用户后续做同一门课或同类实验时更快触发正确流程。

## 触发流程

报告完成后依次询问：

1. 这次结果是否满意。
2. 如果满意，是否要生成或更新专属科目 skill。
3. 如果同意，先输出拟沉淀规则摘要。
4. 用户确认后才写入或更新 skill。

不要在用户未确认时自动创建或修改专属 skill。

## 保存内容

可以保存：

- 课程或实验类型的触发词。
- 常见报告结构。
- 模板格式偏好。
- 截图占位格式。
- 老师或课程偏好的详略程度。
- 常见软件、命令、图表、实验小结结构。
- finalize 时应删除的提示类型。
- 本次流程中被用户认可的稳定规则。

禁止保存：

- 姓名、学号、班级、手机号、邮箱。
- 账号、密码、token、服务器凭据。
- 完整报告正文。
- 原始实验数据、截图、私有源码。
- 任何可直接定位到用户个人或具体作业提交的敏感材料。

## 专属 skill 结构建议

```text
skills/user-subject-<slug>/
  SKILL.md
  references/
    workflow-notes.md
    formatting-notes.md
    iteration-log.md
```

`SKILL.md` 保持短小，负责触发和主流程。细节放入 references。

## 更新策略

只允许确认后追加规则，不自动重写核心流程。

每次更新 `iteration-log.md`，记录：

- 日期。
- 实验类型。
- 用户确认满意的点。
- 新增规则。
- 不应泛化的特殊情况。

如果新经验和旧规则冲突，先向用户说明冲突并等待选择。

## 后续触发

当用户明确说某门课或某类实验，例如“做计网实验报告”“做软工详细设计”“做人工智能实验”，优先使用对应专属 skill。

如果专属 skill 无法覆盖当前任务，退回通用实验报告 skill。
