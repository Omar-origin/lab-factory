# Format Policy

## 支持格式

MVP 稳定支持：

- `.docx` 输入和输出。
- `.md` 输入和输出。

旧 `.doc`、复杂嵌入对象、手写公式、宏文档、特殊学校封面属于最佳努力范围。不要承诺完全保真。

## 通用原则

- 源文件只读，处理副本。
- 有模板时保留模板结构，不从零生成风格完全不同的文件。
- 草稿阶段保留原报告、模板、占位段落和说明文字中的全部原有内容。即使原文写明“可删除”，也只在交付说明中提示，不在草稿中删除。
- 输出格式默认与模板一致；`.docx` 生成 `.docx`，`.md` 生成 `.md`。
- 如果任务要求导出 PDF，默认不处理 PDF 导出，除非用户另行明确要求。
- 生成内容必须附免责声明。

## 写作要求确认

开始生成前，先确认或记录以下写作要求：

- 报告语言。
- 标题字体、字号、颜色、加粗、编号层级。
- 正文字体、字号、颜色、行间距、首行缩进、段前段后。
- 表格样式、表头样式、边框、编号。
- 图片尺寸、位置、图注格式、图文关系。
- 代码、命令、日志是否保留及展示方式。
- 实验小结结构和字数。
- 需要填写的章节、表格、图片位置、封面字段和小结区域。
- 不允许触碰的原有内容范围。
- 实际使用的实验环境、工具、版本、平台和数据文件。

如果用户没有明确要求，使用内置默认要求。默认表暂时留空，待后续补充：

```text
语言：
标题：
正文：
行间距：
颜色：
表格：
图片与图注：
代码/命令：
实验小结：
```

## DOCX 策略

生成或修改中文 DOCX 时：

- 正文格式优先使用用户确认要求；未确认时使用内置默认要求。默认表待添加。
- 图注格式优先使用用户确认要求；未确认时使用内置默认要求。默认表待添加。
- 标题优先复用模板标题样式。
- 表格优先复用模板表格样式。
- 个人信息字段未知时保留清晰占位，例如 `【姓名】`、`【学号】`。
- 避免把 LaTeX 源码直接留在最终 DOCX 正文中。

实现时优先复制模板，再按 `template-editing-policy.md` 在锚点相邻位置插入新段落或补充内容。草稿阶段不要删除或覆盖模板里的封面、页眉页脚、表格结构、占位文字和说明文字。

不要把整篇正文写进表格单元格。表格内只填写该单元格本来对应的局部内容；表格外正文必须找到表格外锚点。

封面个人信息只在用户确认完成实验或进入最终整理时填写。先根据封面字段询问用户，再写入最终版并按用户确认的命名规则重命名输出文件。

## Markdown 策略

Markdown 草稿应使用：

- 清晰标题层级。
- 表格呈现实验数据和对比。
- 代码块呈现代码、命令和日志。
- 截图占位不使用图片语法，除非已有真实图片路径。
- 参考示例模式必须在正文标注参考性质。
- 保留原 Markdown 中已有的说明、占位和可删除文字，等待用户 finalize 前确认是否删除。

Finalize 时只删除用户确认要删的原始提示、命令说明和用户待办，同时保留报告正文需要的代码、结果表格和分析。

## 免责声明

每个报告末尾固定加入：

```text
免责声明：本文档由实验报告辅助工具根据用户提供材料生成，仅供学习参考。使用者需自行核验其中的实验过程、数据、截图和结论，并确认符合课程要求与学术规范。
```

如果学校模板已经有类似声明，可以保留模板声明并补充“学习参考、需自行核验”的含义。

## 格式风险说明

交付说明中要列出无法完全验证的风险，例如：

- 旧 `.doc` 转换后的格式差异。
- 模板含宏、嵌入对象或复杂页眉页脚。
- 公式无法转换为原生 Word 公式。
- 用户未补齐截图导致最终版仍有占位。
