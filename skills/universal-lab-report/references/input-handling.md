# Input Handling

## 输入类型

支持两种入口：

1. 任意路径：用户直接给任务书、模板、源码、数据、截图、文件夹等路径。
2. 标准输入文件夹：用户把材料放入角色命名目录和 `.md` 文件。

不要强迫用户整理成标准文件夹。标准文件夹只是推荐结构，任意路径也要能处理。

## 标准输入文件夹角色

```text
实验任务书/
实验所需文件/
实验报告模板/
成品实验报告/
实验相关课件/
实验原始数据.md
个人信息.md
评分标准.md
输出文件要求.md
目标写作风格.md
```

空目录和空 `.md` 文件可以忽略，不要要求用户删除。

## 任意路径角色识别

根据文件名、目录名、扩展名和内容摘要推测角色：

- `任务书`、`实验指导`、`实验要求`、`assignment`、`lab manual`：任务书。
- `模板`、`template`、`报告格式`、空白表格：报告模板。
- `成品`、`样例`、`参考报告`、`sample`、`example`：成品样例。
- `.py`、`.ipynb`、`.java`、`.c`、`.cpp`、`.js`、`.sql`、项目目录：实验所需文件。
- `.csv`、`.xlsx`、日志、测量记录、截图：原始数据或证据。
- `.ppt`、`.pptx`、教材 PDF、课件：实验相关课件。

如果同一文件可能有多个角色，按任务书、模板、样例、原始数据、课件、实验所需文件的顺序判断；不确定时在工作说明中标记为“待确认角色”，但仍继续处理可确定部分。

## 输出工作区

工作区默认建在最主要输入文件的同级目录。如果用户给的是多个不同目录，选择任务书所在目录；没有任务书则选择第一个输入路径所在目录。

工作区建议：

```text
实验报告助手输出/
  <任务名>-<YYYYMMDD-HHMMSS>/
    source-copy/
    artifacts/
    draft/
    final/
    notes/
```

`source-copy/` 保存完整副本；`notes/` 保存材料清单、证据模式、用户待办和专属 skill 沉淀摘要。

## 文件读取策略

- 先读任务书，再读模板和输出要求。
- 样例报告只读一次用于提取完整度和风格，不用作改写底稿。
- 大型源码目录先清点结构，优先看 README、配置文件、入口文件和数据目录。
- 不读取或保存用户敏感凭据；如果材料里出现账号、密码、token，只在最终说明中提醒用户脱敏。
