# Screenshot Policy

## 总原则

截图要求不能让流程卡死。能从真实材料或可复现结果得到截图时尽量生成；不能生成时，留下可执行的截图提示和用户待办。

## 检查顺序

1. 查找已有图片：`.png`、`.jpg`、`.jpeg`、`.webp`、`.bmp`、`.gif`。
2. 查找已有输出：日志、HTML、Notebook 输出、CSV/Excel、测试报告、图表文件。
3. 判断是否可本地运行：源码、项目、Notebook、SQL、网页、脚本、测试用例。
4. 对软件、网页、数据分析、算法、数据库类实验，尝试合理的最小复现。
5. 如果复现需要私有账号、课堂环境、物理设备、硬件仪器、付费服务或不可用软件，则使用占位。

## 可生成截图的场景

- 静态 HTML 或本地网页。
- Python/Notebook 图表、表格、终端输出。
- 数据库查询结果表。
- 程序运行日志或测试结果。
- 简单 UI 原型或可运行项目。

截图生成后保存到 `artifacts/`，并在报告中引用或提示用户插入。

## 必须占位的场景

- 物理、化学、生物现场操作。
- 实验仪器、硬件接线、课堂软件界面且本地不可复现。
- 需要用户账号、远程服务器、私有系统、付费平台或真实设备。
- 用户明确要求不要自动截图。

占位格式：

```text
【截图：请在 <软件/环境> 中完成 <操作>，截取包含 <关键内容> 的界面】
```

## 用户指导

草稿版中可以保留截图提示。最终版前应询问用户是否已插入截图。

如果用户问“这个图怎么做”，按步骤指导：

- 打开什么软件或文件。
- 执行什么命令或操作。
- 截取哪里。
- 图片插入到报告哪个位置。
- 图注应该写什么。
