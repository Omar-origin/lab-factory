# Template Editing Policy

## 为什么要这样做

已验证的科目专属 skills 能稳定工作的原因，不是因为知道某一门课的答案，而是因为它们先定位模板结构，再在明确锚点附近插入内容。通用 skill 必须复用这个原则。

## 草稿阶段原文保全

草稿版是“在副本上补内容”，不是重写模板。

必须保留：

- 封面页。
- 目录页。
- 说明页。
- 文档变更历史。
- 原模板标题、表格、占位段落。
- 考核结果、成绩、教师评语、批改时间。
- 所有写着“可删除”“填写后删除”“此处填写”的原始提示。

草稿阶段不得删除、合并、重排这些内容。即使某些内容最终明显应删除，也只列为“待用户确认删除项”。

## 锚点优先

生成内容前先建立“模板地图”：

- 段落列表：编号、文本、样式、是否在表格中。
- 表格列表：编号、单元格文本、疑似用途。
- 占位列表：`<...>`、`【...】`、下划线、红字提示、说明文字。
- 章节锚点：实验步骤、实验结果、实验小结、部署环境、系统部署、系统维护等。

每段新增内容必须绑定到一个锚点：

- 占位段落后。
- 对应章节标题后。
- 对应表格单元格内。
- 用户确认的插入位置。

没有锚点时，先问用户，不要自行在文档末尾新建大段内容。

## 禁止整篇塞入表格

如果模板里有大表格或嵌套表格，不要把整篇报告内容写进第一个单元格。

表格只能用于：

- 填写该单元格原本对应的内容。
- 补充该表格要求的数据。
- 保持原表格结构的局部替换。

如果需要在表格外写正文，应定位表格后的段落或对应章节锚点；找不到就询问用户。

## 实验小结插入规则

如果模板已有“实验小结”“实验小结（包括问题和解决办法、心得体会、意见与建议等）”等锚点：

- 不要新建另一个“实验小结”标题。
- 在已有锚点后插入问题、心得、建议内容。
- 保留原锚点文字本身。
- 不要把小结插到前面的说明书框、表格或目录中。

如果模板没有实验小结锚点，才按用户确认的位置新增标题。

## DOCX 实现约束

处理 DOCX 时优先使用底层 XML 或能保留样式的方式：

- 复制现有段落或单元格样式后插入。
- 使用相邻锚点的样式构造新段落。
- 避免用默认 `add_paragraph()` 把内容追加到文档末尾。
- 避免清空整个段落、整个表格或整个 body 后重建。

草稿生成后运行保全检查：

```bash
python3 scripts/compare_docx_preservation.py <source.docx> <draft.docx>
```

如果报告里关键原文缺失，例如目录、说明页、考核表、实验小结锚点缺失，必须修复后再交付草稿。

## Markdown 实现约束

Markdown 也要按锚点处理：

- 保留原标题和说明。
- 在确认的标题下补内容。
- 不删除原占位。
- 不重排未知章节。
